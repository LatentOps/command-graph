# Ordin v0.3.0 release notes — draft

Publication is pending the exact release-candidate and final-version gates.
The current stable tag remains v0.2.0 until the release issue is complete.

Ordin v0.3 extends the local action-review boundary into maintained coding-agent
and MCP workflows. It keeps the deterministic core free of required runtime
dependencies and leaves execution, credentials, sandboxing and approval UI with
the host.

## Changes since v0.2.0

- Bounded live integration sessions retain proposals and correlated observations,
  with optional private persistence for separate hook processes.
- MCP contract pins detect changes in advertised tool contracts; exact server,
  tool and reviewed semantics identities govern trust.
- Codex hooks/plugin assets cover shell, patches, mapped MCP and generic tools
  through the shared gate. Unsupported `ask` output maps conservatively to deny.
- MCP inspect/scaffold/validate/lock separates discovery from reviewed trust.
- Streamable HTTP adds local JSON/SSE/session/auth/timeout handling around the
  same MCP review engine, with an explicit supported protocol profile.
- Opt-in trace capture supports inspection, semantic sanitization, offline replay
  and reviewed promotion into existing regression formats.
- Native macOS validation covers core/integrations and system Bash/Zsh. Linux
  command knowledge stays labeled independently of runtime support.
- Security reporting, threat-model documentation, CodeQL, dependency review,
  immutable action pins and release checksum/SBOM/attestation checks are maintained.

Correctness fixes include Zsh's read-only status parameter, absolute HTTP
deadlines and unusable timed-out sessions, preserved MCP request correlation,
pending-action retention under history pressure, relative repository context,
concurrent audit writers, malformed JSON/configuration bounds, and non-finite
optional semantic scores. No safety or latency threshold was relaxed.

## Compatibility and upgrade notes

Python 3.10–3.13 is supported on the maintained Linux matrix; macOS 15/Apple
Silicon is tested with Python 3.13. Native Windows is not a supported release
target. See the full [matrix](../compatibility.md).

Valid v0.2 action/review/trace forms remain readable. Invalid typed values,
unknown named members and ambiguous configuration JSON are rejected explicitly.
Policy working-directory prefixes must be absolute POSIX paths; missing or
relative repository context remains unknown. The [public surface inventory](../public-compatibility-0.3.md)
distinguishes stable v1 contracts from experimental capture/report layouts.

State/audit/capture remain opt-in and should use separate private files. A
configuration/version mismatch requires an explicit session reset. Review host
hooks after upgrades; an installed hook is not proof that the host enabled it.
MCP discovery metadata is not executable semantics, and contract pins cannot
verify a server's implementation.

## Evidence and release integrity

The exact candidate revision, environment, workloads and measurements are
recorded by the [release preparation gate](../release-preparation-0.3.md), not
copied from older reports. Evaluation uses finite deterministic/local fixtures;
it does not estimate production prevalence or complete agent-session latency.

Release assets include a wheel/source archive, SHA-256 manifest, source/version
identity, CycloneDX build inventory and verified provenance bundle. Follow
[release verification](../releasing.md) before installation. Checksums and
attestations identify bytes and build origin; they do not prove source safety.

After publication, install the v0.3.0 tag or published wheel in a new environment
and run the [offline quickstart](../quickstart.md). `main` continues as unreleased
development. The release process will finalize this notice and stable links.
